# ADR-0002: History-based persistent naming for faces and edges

- Status: Accepted
- Date: 2026-10-16

## Context

Parametric features reference topology of earlier features ("fillet these edges", "sketch on this face", "hole on
this face"). OCCT identifies faces and edges by transient indices that change whenever an upstream dimension or
feature changes. References stored as indices break silently: the classic topological-naming problem.

## Decision

1. **Faces carry persistent names derived from feature history.** Each feature names the faces it creates from its
   own semantics, e.g. extrude `f2:start`, `f2:end`, `f2:side:l9` (side face generated by sketch line `l9`), hole
   `f5:wall:0`, box primitive `f1:+x`, fillet `f6:fillet[A|B]`, pattern copies `f7:3:<name>`. Names are propagated
   through later operations using OCCT's history API (`Modified`, `Generated`, `IsDeleted` on every builder), so a
   face split or trimmed by a boolean keeps its lineage. A face can hold several names after merges.
2. **Edges are referenced by the pair of faces they separate** (`{kind: "between", faces: [A, B]}`), optionally with a
   geometric hint point used only to disambiguate multiple matches. Other edge references: all edges of a named face,
   all edges of the body, and an explicit "nearest to point" fallback that is flagged as fragile.
3. **Resolution failure is an error, never a guess.** An unresolvable reference fails the feature with code
   `unresolved_reference`, names the missing face, and asks the user to re-select. Ambiguous matches use the hint.
4. **The UI shows stability.** Faces without a history-derived name (for example on imported solids) are marked
   "unstable name" in the inspector so users know references to them may not survive edits.

## Verification

Kernel tests change upstream dimensions and check that downstream fillets, holes and sketches still resolve to the
geometrically correct entities (`test_fillet_reference_survives_upstream_dimension_change`), that impossible
references report `unresolved_reference`, and that recompute is deterministic.

## Consequences

- References survive dimension changes, reordering that keeps dependencies valid, and most boolean splits.
- Topology changes that legitimately remove a face (e.g. a cut deleting it) surface as clear errors to fix.
- Imported STEP solids have no feature history; faces get positional names and are marked unstable.
- Names are part of the document format; changing a feature's naming scheme requires a schema migration.
